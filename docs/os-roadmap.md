# 操作系统支持计划

目标是在五级流水模拟器上运行适配 RV32 的轻量级操作系统。本文描述后续工作，不代表当前已具备系统启动能力。

## 当前状态

已实现 RV32IMA 流水核心、CSR 寄存器文件和 M/S/U 特权级状态。异常到达 WB 后记录原因并停止模拟，尚未进入陷阱处理程序。A 扩展仅支持数组 RAM。

系统层支持原始二进制装载、物理总线和项目内实现的 RAM/MMIO 映射。尚未实现陷阱返回、中断、Sv32、完整设备和 ELF 装载。

## 模块边界

核心负责指令执行、CSR、特权级、异常和地址翻译。系统层负责内存映射、装载和设备，参考 MARSS/TinyEMU 的设计，在项目内实现所需逻辑。

设备通过适配接口读取时间、查询处理器状态和更新中断待决位。PC、寄存器、CSR 和时间状态保持单一来源，不另建一套独立 CPU 状态。具体接口应在接入设备时确定。

## 实施顺序

1. 完善陷阱入口、`mret/sret`、状态位更新和委托。验证故障前的指令正常提交，故障后的指令无副作用。
2. 接入定时器、中断和 UART。用裸机程序验证特权级切换、中断进入与返回、控制台输出。
3. 实现 Sv32 页表遍历、权限检查、缺页和 `sfence.vma`，同时接入取指与数据访存。按需增加 TLB。
4. 将原子访存接入系统内存，补齐 `fence.i` 和系统环境下的排序、保留失效规则。
5. 支持 ELF 的多段装载、入口和零初始化区域，并明确启动参数、栈和内存布局。
6. 按目标内核需要接入 PLIC、VirtIO 等设备，逐步验证启动、控制台和 shell。

目标内核须支持 RV32；镜像位宽、地址空间和启动约定应在系统联调前确认。

## 验收方法

每一步先使用裸机定向程序验证，再进行参考模型对照。特权指令和异常可扩展现有 Spike 工具；系统启动使用相同镜像与参考模拟器比较控制台日志和关键状态。

主要检查点包括：只读 CSR 和越权访问、陷阱 PC 与原因、返回后的特权级、中断响应、取指和访存缺页、原子操作以及 ELF 装载结果。最终以目标内核进入 shell 作为系统阶段的验收条件。

现有差分只覆盖 RV32IM 正常提交，不能替代这些检查，范围见 [Spike 差分验证](spike-diff.md)。

## 执行效率与轨迹

先测量实际内核的启动耗时和轨迹体积，再决定是否增加功能快进。功能路径与周期路径应共享架构语义，切换前处理完在途指令，并保持寄存器、CSR、内存和设备时间一致。

长程序应支持按范围采集轨迹，避免始终输出完整阶段和提交日志。功能快进和轨迹窗口目前都未实现，命令行名称与切换规则待设计。

## 内存布局

计划采用便于与参考平台对照的物理地址布局，接入设备时再确认范围与启动固件要求：

| 区域 | 计划基址 |
| --- | --- |
| 复位入口 | `0x00001000` |
| CLINT | `0x02000000` |
| PLIC | `0x0c000000` |
| UART | `0x10000000` |
| VirtIO | `0x10001000` |
| RAM | `0x80000000` |

当前 `0x10000000` 映射的是 项目内的测试锁存器，不是 UART。现有二进制入口与装载地址相同，尚未采用上述复位入口。当前接口见 [程序装载与提交轨迹](loader-trace.md)。

## 范围限制

本计划以单核、顺序流水和基本系统设备为范围。多核一致性、乱序执行、网络、图形和详细缓存时序暂不纳入。加入异步中断或更多访存主体前，需重新检查提交边界和原子写入的不可取消条件。
