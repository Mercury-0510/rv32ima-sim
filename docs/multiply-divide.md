# 乘除单元

M 扩展使用非流水化多周期单元，共享一个 EX 槽。首次进入 EX 时计算结果，等待配置的周期数后进入 MEM，最终在 WB 写回寄存器。

## 执行时序

| 指令 | 默认 EX 延迟 | 额外等待 | 无阻塞时从 IF 到 WB |
| --- | --- | --- | --- |
| MUL、MULH、MULHSU、MULHU | 3 拍 | 2 拍 | 7 拍 |
| DIV、DIVU、REM、REMU | 32 拍 | 31 拍 | 36 拍 |
| 普通整数 ALU | 1 拍 | 0 拍 | 5 拍 |

这些延迟是本模型的配置，不代表 ISA 要求或真实电路的测量值。除零和有符号除法溢出使用相同延迟，没有提前完成或结果复用。独立乘除指令也必须串行占用 EX。

EX 等待期间保留自身锁存器、ID 和取指 PC，较老的 MEM/WB 指令继续推进。完成当拍允许 ID 处理下一条指令；存在数据依赖时仍需等待 WB，当前没有转发。

MEM 阻塞优先于 EX。较老 AMO 占用 MEM 时，乘除计数器暂停。较老异常阻止 EX 推进，被分支丢弃的指令不启动。周期预算耗尽后保留中间状态，后续调用 `in_core_run()` 继续执行。

## 状态与配置

`InsnLatch.m_result_ready` 标记结果已经计算，`ex_cycles_left` 保存剩余 EX 推进次数，避免重复计算。未完成时保留 `next_execute`，不向 `next_memory` 发送指令。

`INCore.config.mul_cycles` 和 `div_cycles` 保存延迟。`INCore.stats.execute_stalls` 记录乘除等待拍数，不包含数据冒险停顿或 MEM 阻塞。

在初始化后、第一次运行前配置：

```c
if (!in_core_set_m_latency(&core, 3, 32)) {
    /* 延迟必须非零，且模拟尚未开始。 */
}
```

成功返回 1，失败返回 0 且不修改配置。延迟为 1 表示单拍 EX。运行中不要直接修改配置字段；重新初始化会恢复默认 3/32 拍并清除中间状态和统计。

## 验证

`tests/test_rv32i.c` 检查全部 8 条 M 指令的运算结果，以及 1、2、5、32 拍配置下的时序。测试包括前端保持、写回时机、数据相关、连续乘除、AMO 反压、预算切分后恢复和异常冲刷。

构建与完整回归命令见 [README](../README.md)。

## 设计边界

设计参考 MARSS 顺序核心对功能计算和执行延迟的分离。当前没有实现并行功能单元、逐级乘法流水或逐位除法算法；32 拍等待不等于 32 次除法迭代。

扩展为流水化乘法器时，需要增加每级状态和输出仲裁，并分别验证延迟与吞吐率。研究迭代除法时，需要显式维护商、余数和迭代计数。
