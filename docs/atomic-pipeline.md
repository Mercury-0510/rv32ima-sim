# 原子访存

A 扩展实现 9 条 AMO.W 和 LR.W/SC.W，使用阻塞式 MEM 状态机。目前仅支持单 hart 独占的数组 RAM，尚未接入总线、MMIO、缓存或其他并发访存者。

## 流水职责

ID 检查指令编码并等待源寄存器，EX 将 rs1 保存到 `InsnLatch.mem_addr`。MEM 检查地址并完成原子操作，WB 写回结果和记录退休，不重复访问内存。

`result` 保存内存旧值或 SC 状态，`mem_value` 保存待写数据，`atomic_phase` 保存执行阶段。这些状态随锁存器保留，暂停后不会重复读取或写入。

## 执行时序

| 指令 | 第一次 MEM | 第二次 MEM | 第三次 MEM | 无阻塞时从 IF 到 WB |
| --- | --- | --- | --- | --- |
| AMO.W | 检查地址、读取旧值 | 计算新值 | 写入并送往 WB | 7 拍 |
| LR.W | 检查地址、读取、建立保留并送往 WB | 无 | 无 | 5 拍 |
| SC.W | 检查地址、检查并消费保留 | 条件写入并送往 WB | 无 | 6 拍 |

SC 成功返回 0，保留检查失败返回 1，两种情况都占两拍 MEM。地址错误在第一拍生成异常，下一拍由 WB 报告，不进入后续阶段。固定延迟是本模型的选择，不是 ISA 要求。

AMO 前两拍、SC 第一拍设置 `memory_stalled`。此时 MEM 保留更新后的状态，EX、ID 和取指 PC 保持，`next_commit` 为空。较老 WB 指令仍可提交一次；MEM 完成当拍放行 EX。

`INCore.stats.memory_stalls` 对每条正常 AMO 增加 2、SC 增加 1、LR 增加 0。`stats.stalls` 只统计寄存器数据冒险，不重复计入 MEM 阻塞。

## 内存写入时机

每拍先执行 WB，再执行 MEM。原子指令进入 MEM 时，较老指令已经提交；如果较老指令在 WB 发生异常，MEM 不会执行。因此原子指令可以在最后一拍 MEM 写内存，下一拍 WB 再写寄存器和退休。

MEM 忙时，年轻指令无法访问数据端口，同一 hart 的访存不会插入 AMO 的读改写过程。周期预算耗尽只暂停推进，不清除事务状态。

这一保证依赖单 hart、同步 RAM 和无异步取消的模型。引入共享 RAM、DMA、中断或晚到的访存错误时，需要重新定义仲裁、取消和保留失效规则。

## LR/SC 保留规则

- 每个 hart 通过 `reservation_valid` 和 `reservation_addr` 保存一份对齐的 4 字节保留。LR 成功后建立保留，新 LR 覆盖旧保留。
- SC 先检查地址，再检查保留。保留有效且地址相同才成功；检查后立即消费保留，无论成功或失败。
- 普通 SB/SH/SW 或 AMO 写入保留范围内任一字节，都会使保留失效，即使写入值未变。非重叠写入不影响保留。
- 地址异常的 LR/SC 不读写内存，也不修改保留。SC 没有保留时仍检查地址。
- 初始化清空保留；被分支丢弃的 LR/SC 不进入 MEM，不影响保留。

## 排序与异常

四种 aq/rl 组合均接受，延迟相同。当前访存顺序推进，原子操作阻塞数据端口；该模型未验证多 hart 弱内存行为或 I/O 排序。

译码只接受 `.W` 和已实现的 11 种 funct5。`.D`、未知编码和 rs2 非零的 LR 均报告非法指令。LR 的未对齐和访问故障原因为 4/5，SC 与 AMO 为 6/7。锁存器内部保存 `cause + 1`，WB 报告异常并停止，不增加退休数。
